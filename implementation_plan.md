# 🏗️ BTN Prototype — Phase 1 Architecture Plan

## Scope: Login + Admin User Management + Lead Phone Verification

---

## 📋 What We Are Building (Only 3 Features)

| # | Feature | Who Uses It | What It Does |
|---|---------|-------------|-------------|
| 1 | **Login Page** | All users | Email + password login with JWT token, light/dark mode toggle |
| 2 | **Admin Panel** | Platform Owner (BTN Admin) | Add new users, assign roles, activate/deactivate users |
| 3 | **Lead Phone Verification** | BTN Verification Team | See list of unverified leads, call them, mark as Verified/Rejected |

## 🔌 API Endpoints (15 Total)

### 🔐 Auth APIs (3 endpoints)

---

#### `POST /api/auth/login`

**Who can call**: Anyone (no token needed)

**Request:**
```json
{
  "email": "admin@btn.com",
  "password": "Admin@123"
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs...",
    "refreshToken": "d4f5e6a7-b8c9-...",
    "expiresIn": 3600,
    "user": {
      "id": "a1b2c3d4-...",
      "fullName": "BTN Admin",
      "email": "admin@btn.com",
      "role": "PlatformOwner"
    }
  }
}
```

**Response (401 Unauthorized):**
```json
{
  "success": false,
  "error": "Invalid email or password"
}
```

**Business Rules:**
- Check if email exists in `users` table
- Verify password hash using BCrypt
- Check if user status is "Active" (reject if Inactive/Suspended)
- Generate JWT access token (expires in 1 hour)
- Generate refresh token (expires in 7 days), save in `refresh_tokens` table
- Update `last_login_at` in users table
- Log in `audit_logs`: action = "Auth.Login"

---

#### `POST /api/auth/refresh`

**Who can call**: Anyone with a valid refresh token

**Request:**
```json
{
  "refreshToken": "d4f5e6a7-b8c9-..."
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiIs... (new token)",
    "refreshToken": "e5f6g7h8-c9d0-... (new refresh token)",
    "expiresIn": 3600
  }
}
```

**Business Rules:**
- Find refresh token in `refresh_tokens` table
- Check if token is not expired and not revoked
- Revoke old refresh token (`is_revoked = true`)
- Generate new access token + new refresh token
- Return both new tokens

---

#### `POST /api/auth/logout`

**Who can call**: Authenticated users (needs JWT token)

**Request Header:** `Authorization: Bearer {accessToken}`

**Request:**
```json
{
  "refreshToken": "d4f5e6a7-b8c9-..."
}
```

**Response (200 OK):**
```json
{
  "success": true,
  "message": "Logged out successfully"
}
```

**Business Rules:**
- Revoke the refresh token (`is_revoked = true`)
- Log in `audit_logs`: action = "Auth.Logout"

## 🔄 Frontend API Interceptor Logic

```
Every API call from React:
    │
    ├─ Attach JWT token in header: Authorization: Bearer {token}
    │
    ├─ If API returns 401 (token expired):
    │   ├─ Automatically call POST /api/auth/refresh
    │   ├─ If refresh succeeds → Retry original request with new token
    │   └─ If refresh fails → Redirect to /login (session expired)
    │
    └─ If API returns 403 (forbidden):
        └─ Show "You don't have permission" message
```
